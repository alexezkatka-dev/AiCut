# Auto Editor — техническое задание

Локальная программа для Windows. Получает исходники и сценарий (или ролик-референс), сама подбирает и обрезает дубли, собирает черновик в CapCut и короткое MP4-превью. Человек открывает черновик, правит спорные места и экспортирует.

Версия ТЗ: 1.0 (17.10.2026)

---

## 1. Что программа делает

На входе:
- папка с исходниками (дубли с телефона, имена вида `IMG_4821.MOV`);
- **режим A «Под озвучку»**: готовая озвучка (MP3 из ElevenLabs) + сценарий с кадрами;
- **режим B «По референсу»**: ролик-образец (локальный файл) + при желании своя озвучка.

На выходе:
- черновик в CapCut с дорожками: видео, озвучка, музыка, надписи, субтитры;
- `preview.mp4` в 540p для быстрой проверки с телефона;
- `report.html` — список кадров с миниатюрами, уверенностью подбора и альтернативами.

Главный принцип: **ИИ решает, движок исполняет.** Оба режима создают один файл `edit_plan.json`. Сборщик CapCut и сборщик превью читают только его. Модули не обходят этот файл.

## 2. Конвейер

```
            ┌───────────────┐
 исходники ─►  1. Индексатор ├──► media_index.db (кадры, эмбеддинги, движение, качество)
            └───────────────┘
                                          │
 сценарий + озвучка ─► 2A. Планировщик A ─┤
 референс ──────────► 2B. Планировщик B ──┤──► slots.json (что нужно и на сколько секунд)
                                          ▼
                                 3. Подборщик кадров ──► edit_plan.json
                                          │
                       ┌──────────────────┼───────────────────┐
                       ▼                  ▼                   ▼
              4. Сборщик CapCut   5. Сборщик превью     6. Отчёт / окно проверки
```

Каждый шаг пишет результат в `work/<имя_проекта>/`. Любой шаг можно перезапустить отдельно, а уже посчитанное берётся из кэша.

## 3. Форматы данных

### 3.1. Сценарий для режима A — `shot_list.md`

Формат совпадает с тем, как пишутся сценарии канала: кадр и текст озвучки идут вместе. Пример — `examples/shot_list.example.md`.

```
## K01 | hook
SHOT: close-up, hand slicing a dry chicken breast on a wooden board
VO: Your chicken breast is dry, and it's not your fault.
TEXT: DRY AGAIN?
RU: Твоя куриная грудка сухая, и ты не виноват.
```

Правила разбора:
- `## K<номер> | <роль>`: роль из списка `hook`, `problem`, `step`, `result`, `cta`, `broll`;
- `SHOT:` — описание кадра **на английском** (по нему идёт поиск в исходниках);
- `VO:` — строка озвучки ровно как в TTS-файле; метки `{{pause=N}}` при разборе удаляются;
- `TEXT:` — необязательная надпись на экране;
- `RU:` и любые другие строки игнорируются.

### 3.2. Слоты — `slots.json`

Промежуточный результат планировщика: список «что нужно и сколько длится».

```json
{
  "source": "voiceover",
  "slots": [
    {"id": "K01", "role": "hook", "shot": "close-up, hand slicing a dry chicken breast",
     "start": 0.00, "end": 2.84, "text": "DRY AGAIN?"}
  ]
}
```

### 3.3. Монтажный план — `edit_plan.json`

Центральный формат. Полный пример — `examples/edit_plan.example.json`. Описывается Pydantic-моделями в `autoedit/plan.py`.

- `project`: имя, ширина, высота, fps (по умолчанию 1920×1080, 30);
- `video[]`: `slot_id`, `source`, `src_in`, `src_out`, `start`, `duration`, `speed`, `zoom_from`, `zoom_to`, `confidence` (0–1), `alternatives[]`, `needs_review`;
- `audio[]`: `kind` (`voiceover` / `music` / `sfx`), `source`, `start`, `duration`, `volume`;
- `text[]`: `content`, `start`, `duration`, `style` (имя пресета);
- `subtitles`: путь к SRT или `null`.

Все времена указываются в секундах (float). В микросекунды для CapCut переводит только сборщик.

### 3.4. Индекс исходников — `media_index.db` (SQLite)

- `files`: путь, хэш (размер + mtime + первые 1 МБ), длительность, fps, разрешение, ротация, время съёмки;
- `samples`: файл, время, эмбеддинг (кадры раз в 0,5–1 с), резкость, яркость, энергия движения;
- `takes`: активные участки внутри файла (руки в кадре и есть движение), начало и конец.

Повторная индексация пропускает файлы с тем же хэшем.

## 4. Модули и технологии

| Модуль | Файл | Технология |
|---|---|---|
| Настройки | `autoedit/config.py` | YAML + Pydantic |
| Монтажный план | `autoedit/plan.py` | Pydantic v2 |
| Индексатор | `autoedit/index/` | FFmpeg/ffprobe, OpenCV, PySceneDetect, open_clip (SigLIP) |
| Распознавание речи | `autoedit/asr.py` | faster-whisper, пословные таймкоды |
| Планировщик A | `autoedit/planner_vo.py` | разбор `shot_list.md` + выравнивание текста (rapidfuzz) |
| Планировщик B | `autoedit/planner_ref.py` | PySceneDetect + faster-whisper + SigLIP |
| Подборщик | `autoedit/matcher.py` | numpy, правила из раздела 5 |
| Сборщик CapCut | `autoedit/build_capcut.py` | **pycapcut==0.0.4** |
| Сборщик превью | `autoedit/build_preview.py` | FFmpeg (filter_complex) |
| Отчёт | `autoedit/report.py` | HTML + миниатюры |
| Окно | `app.py` | Gradio (локальная страница в браузере) |
| CLI | `autoedit/cli.py` | Typer |

Почему Gradio, а не PySide6: окно собирается в 3–4 раза быстрее, Claude Code его надёжно поддерживает, а миниатюры, видео и таблицы есть из коробки.

Python 3.11 (не 3.13: часть ML-библиотек под Windows отстаёт). Все зависимости закреплены в `requirements.txt` с версиями.

ИИ-модели работают локально и бесплатно. Внешние API в первой версии не используются. Описание кадров через Claude API — отдельная опция на этапе 6, по умолчанию выключена.

## 5. Алгоритмы

### 5.1. Индексация
1. ffprobe: длительность, fps, разрешение, ротация (телефонные MOV часто повёрнуты, это нужно учитывать).
2. Кадры раз в 0,5 с в 384 px, через FFmpeg в память.
3. Для каждого кадра: эмбеддинг SigLIP, резкость (дисперсия лапласиана), яркость, энергия движения (разница с предыдущим кадром).
4. Активные участки (`takes`): сглаженная энергия движения выше порога. Сюда же попадает обрезка «мёртвых» начала и конца дубля, когда рука тянется к телефону.

### 5.2. Планировщик A — выравнивание озвучки
1. faster-whisper распознаёт MP3 озвучки с пословными таймкодами (модель `small.en` на CPU, `medium.en` при наличии GPU).
2. Строки `VO:` склеиваются в одну последовательность слов, затем выравниваются с распознанными словами (rapidfuzz + динамическое программирование). Ошибки распознавания допустимы.
3. Слот длится от первого слова своей строки до первого слова следующей строки. Паузы остаются в предыдущем кадре.
4. Если строку выровнять не удалось, слот получает длительность пропорционально числу слов и флаг `needs_review`.

### 5.3. Подборщик кадров
Для каждого слота считается оценка каждого активного участка:

```
score = 0.55 · sim(SHOT, кадры участка)      # SigLIP: текст ↔ изображение, максимум по кадрам
      + 0.20 · order_prior                    # снимали по порядку сценария: участок «на своём месте» во времени
      + 0.15 · quality                        # резкость и экспозиция
      + 0.10 · duration_fit                   # участок не короче слота
```

- Веса задаются в `config.yaml`.
- Внутри выбранного участка берётся окно длиной в слот с максимальным движением (действие в центре кадра, а не в начале).
- Один и тот же отрезок исходника не используется дважды (перекрытие > 30%).
- Сохраняются 3 альтернативы.
- `confidence` < порога (по умолчанию 0,35) или разрыв между первым и вторым местом < 0,03 → `needs_review = true`.
- Участок короче слота: сначала замедление до 0,8×, затем добор вторым дублем того же кадра. Стоп-кадр никогда не ставится.

### 5.4. Оформление (профиль `profiles/food_long.yaml`)
- Зум: медленный наезд 1,00 → 1,06 на кадрах `step`, быстрый 1,00 → 1,12 на `hook`.
- Надписи: пресет «bold» — белый текст, чёрная обводка, нижняя треть; пресет «accent» — жёлтый.
- Музыка: постоянная громкость 0,12; на этапе 6 добавляется приглушение под озвучку.
- Субтитры: SRT из пословных таймкодов, не длиннее 32 символов в строке; включаются флагом.

### 5.5. Планировщик B — по референсу
1. PySceneDetect (`AdaptiveDetector`) делит ролик на сцены, получаются длительности слотов.
2. Для ключевого кадра каждой сцены подбирается описание: SigLIP сравнивает кадр со словарём кухонных действий из `profiles/actions_kitchen.txt` (≈200 фраз) и берёт 3 лучших.
3. faster-whisper расшифровывает речь референса и привязывает её к сценам (для понимания структуры, не для копирования).
4. Получается `slots.json`. Перед подбором человек может поправить описания в окне.
5. Отдельно сохраняется «профиль темпа»: средняя длина кадра, длина хука, частота зумов. Его можно применить в режиме A.

Ролик конкурента используется как образец темпа и структуры. Текст и кадры в итоговом видео всегда свои.

## 6. Сборщик CapCut

- Библиотека: `pycapcut==0.0.4`. В версии 0.1.0 автор меняет API: `add_track` убирается. Обновляться только осознанно.
- Совместимость, заявленная библиотекой: проверено на CapCut до 9.5.0.4050. Работает только **международный CapCut**: JianYing 6+ шифрует проекты.
- Папка черновиков по умолчанию: `C:\Users\<имя>\AppData\Local\CapCut\User Data\Projects\com.lveditor.draft`. Путь задаётся в `config.yaml`.
- Имя черновика: `AE_<ГГГГММДД-ЧЧММ>_<имя_проекта>`. **Существующие черновики никогда не перезаписываются и не изменяются.**
- Если CapCut был открыт во время сборки, новый черновик может не появиться в списке до перезапуска. Программа сообщает об этом.
- Экспорт в MP4 из CapCut делается вручную. Автоэкспорт библиотека не поддерживает.

Проверенный вызов API (на нём основан сборщик):

```python
import pycapcut as cc
from pycapcut import trange_seconds as ts, KeyframeProperty as KP

folder = cc.DraftFolder(drafts_dir)
script = folder.create_draft(name, 1920, 1080, 30)
script.add_track(cc.TrackType.video).add_track(cc.TrackType.audio).add_track(cc.TrackType.text)

seg = cc.VideoSegment(src_path, ts(start, duration=dur), source_timerange=ts(src_in, duration=dur))
seg.add_keyframe(KP.uniform_scale, 0, 1.00)
seg.add_keyframe(KP.uniform_scale, cc.tim(f"{dur}s") - 1, 1.06)
script.add_segment(seg)

script.add_segment(cc.AudioSegment(vo_path, ts(0, duration=vo_len)))
script.add_segment(cc.TextSegment("DRY AGAIN?", ts(0, duration=2)))
script.save()
```

Несколько дорожек одного типа создаются с именами (`track_name`): `video_main`, `audio_vo`, `audio_music`, `text_overlay`, `text_subs`.

Запасные пути, если черновик не открывается в установленной версии CapCut:
1. Режим шаблона: `ScriptFile.load_template()` на основе собственного незашифрованного черновика пользователя и замена материалов.
2. Только превью: FFmpeg собирает полный MP4 в 1080p по тому же `edit_plan.json`.

## 7. Окно программы (Gradio)

Вкладки:
1. **Проект**: имя, режим (A/B), выбор файлов и папок, профиль, кнопка «Собрать».
2. **Проверка**: таблица слотов. В строке: миниатюра выбранного кадра, текст VO, уверенность, 3 альтернативы. Клик по альтернативе меняет кадр в `edit_plan.json`. Спорные строки подсвечены.
3. **Результат**: превью, кнопка «Пересобрать черновик», ссылка на папку проекта.

Запуск двойным щелчком по `run.bat`. Браузер открывается сам.

## 9. Этапы и критерии приёмки

Каждый этап заканчивается проверкой на реальном материале. Следующий этап не начинается, пока не выполнен критерий текущего.

| # | Этап | Критерий приёмки |
|---|---|---|
| 0 | Проверка CapCut | Тестовый черновик (2 клипа с обрезкой, зум, озвучка, надпись) открывается в CapCut пользователя и воспроизводится без ошибок |
| 1 | Каркас + сборщики | `edit_plan.example.json`, написанный вручную, превращается в черновик CapCut и `preview.mp4` с совпадающими таймкодами (±1 кадр) |
| 2 | Индексатор | Папка из 30 реальных дублей индексируется, повторный запуск < 10 с; поиск по тексту находит нужный дубль в топ-3 для 8 из 10 запросов |
| 3 | Режим A | Реальный ролик (сценарий + озвучка + дубли) собирается в черновик; ≥ 70% кадров верны без правок; время ручной доводки записано в PROGRESS.md |
| 4 | Окно + проверка | Весь режим A запускается из окна; замена кадра на альтернативу и пересборка занимают < 1 мин |
| 5 | Режим B | Референс 1–2 мин делится на сцены с точностью склеек ±2 кадра; черновик собирается из своих исходников по темпу референса |
| 6 | Доводка | Приглушение музыки под голос, субтитры, профили темпа, опционально описание кадров через Claude API, вертикальная версия 9:16 |

## 10. Ограничения и риски

- **Формат CapCut не документирован** и меняется с обновлениями. После обновления CapCut нужно перезапустить этап 0. В CapCut стоит отключить автообновление.
- SigLIP плохо различает похожие действия («перевернуть» / «положить» на сковороду). Здесь помогают порядок съёмки и окно проверки. Ожидаемо 20–30% кадров требуют подтверждения.
- Если в исходниках нет нужного кадра, программа ставит лучшее, что есть, помечает `needs_review` и ничего не выдумывает.
- Скорость на CPU: индексация ~1–2 мин на 10 мин исходников, распознавание 10-минутной озвучки ~1–3 мин.
- Под Windows пути могут содержать пробелы и кириллицу. Все вызовы FFmpeg делаются через список аргументов, без сборки строки команды.
